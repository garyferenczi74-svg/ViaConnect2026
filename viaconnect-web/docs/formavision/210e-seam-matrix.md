# Prompt 210e Seam Matrix (Section 5 seams)

Date: 2026-07-09. Branch: feat/210e-integration (worktree, base 30d686bf).
Source of truth for seam names, producer/consumer file:line, and STEP-0 status:
docs/formavision/210e-seam-map.md (the committed STEP 0 seam map).

This matrix has one row per Section-5 seam. The Status column carries the STEP-0
reading verbatim. The Automated test column names the deterministic test id or
file that CI runs; where full verification is live-only, the cell states honestly
which part CI covers and which part is manual / live-smoke.

Row count reconciliation: the E1 brief refers to "14 seams". The committed seam
map (210e-seam-map.md, Section 2), which is the named source of truth for seam
names and producer/consumer lines, enumerates 15 seam rows. This matrix mirrors
all 15 so no Section-5 seam is left undocumented; the extra row over the brief's
count is Guardrails / CI, retained here as a first-class seam.

Two seams carry a Gary-decided behavior for 210e:

- Telemetry: walk step 10 (confirm the 12 events arrive) is an SQL verification
  against the analytics_events table with a fixture user, NOT a dashboard build.
  CI covers the catalog + sink + PII-clean payload shape deterministically; the
  live-arrival of the 12 events in analytics_events is the manual / live-smoke
  SQL check (walk step 10), never headless CI.
- Region tap to protocol: the whole-protocol landing is ACCEPTED. The tap opens
  the real GET /api/protocol/synthesis whole-protocol panel, not a region-filtered
  path. Region targeting is deferred to a future prompt (new engine scope, banned
  here).

Legend for Status: WIRED (producer and consumer both connected and behaving),
PARTIAL (one side connected, a documented gap remains), gated (blocked on an
external deliverable not built in 210e).

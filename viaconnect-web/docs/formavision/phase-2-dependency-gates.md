# Phase 2 Dependency Gates

Prompt #169e Phase 1 deliverable, per Section 4 and the acceptance criteria in
Section 10. This document records the three Phase 2 dependency gates and the
deferred Phase 2 work, reconciled to the shipped reality rather than the idealized
spec. Every gate below is currently UNMET. None of the deferred capabilities exist
in the codebase yet.

Branch: feat/prompt-169e-phase1. Date: 2026-05-31.

## Naming reality (read first)

The spec referred to FormaVision modules under `src/modules/body-tracker/formavision`
and to a `body_scans` table. Phase 1 was built under the existing Body Scan paths;
there is no `src/modules/body-tracker` directory, the real table is
`body_photo_sessions`, and the only "FormaVision" string in the code is a comment
stating the rebrand does not exist here. Read every path below as Body Scan code.
The FormaVision rebrand (Prompt #169c) is not in the codebase.

## Gate A: parametric body model

Decision required: either secure an SMPL-X commercial license, or commit to a
MediaPipe GHUM mesh fallback, as the basis for a higher fidelity, landmark dense
avatar.

Real current state (honest): NEITHER path is in the codebase. The avatar that ships
today is a CUSTOM primitive parametric mesh, scaled spheres (ellipsoids) and
cylinders generated by `src/lib/arnold/scanning/avatarMeshGenerator.ts` and driven
by 9 measurement parameters. It is NOT SMPL-X and it is NOT a MediaPipe GHUM mesh.
A repository wide search for "SMPL", "smpl", "GHUM", and "ghum" returns no matches
(see `docs/licensing/smpl-x-commercial-license.md` and
`docs/formavision/avatar-inspection-v1.md`). To be precise about MediaPipe: the
pipeline does use MediaPipe Pose (BlazePose, Apache 2.0) for 2D landmarks that feed
the measurement numbers, but it does NOT use the MediaPipe GHUM 3D body mesh; the
3D mesh is the primitive mannequin.

Because Phase 1 ships none of the SMPL family assets, no SMPL-X commercial license
is required for what shipped today, and the shipped human geometry stack is
entirely Apache 2.0. The SMPL-X licensing question is preserved as a pending Gary
decision for a future higher fidelity avatar, with options recorded in the
licensing doc (stay primitive; use a permissive or Farmceutica owned mesh; or
license SMPL-X commercially). No commitment to SMPL-X is made or implied.

Gate A is UNMET: the parametric body model decision has not been taken and neither
a licensed SMPL-X path nor a GHUM mesh fallback exists in the code.

## Gate B: Tier B clinical validation cohort (the long pole)

What the gate requires:

- A clinical validation cohort of 100 to 200 participants.
- DEXA and the ViaConnect scan performed on the same day for each participant.
- Segmental DEXA data captured (per region composition, not whole body only).
- The model trained AND validated against that reference.
- A validation report filed.
- Budget of 40,000 to 80,000 USD authorized for the study.

Real current state (honest): UNMET. No cohort has been recruited, no data has been
collected, and no results exist. Both validation records are explicit placeholders
that must not contain invented results:
`docs/validation/body-scan-v1-clinical-validation.md` (external clinical study,
status PENDING, NOT YET RUN) and `docs/validation/body-scan-v1-tier-a-internal.md`
(internal sanity check, status PENDING, NOT YET RUN). Until both clear and Gary
signs off, no DEXA equivalence or accuracy claim may appear on any customer facing
surface; the underlying Navy and CUN-BAE literature figures are design targets
only, not ViaConnect's validated accuracy.

This is the long pole for Phase 2. Realistic timeline: roughly 3 to 4 months for
recruitment plus same day DEXA and scan data collection, plus about 1 month for
model training and validation on the resulting data. Gates A and C can be worked in
parallel, but Phase 2 cannot complete until this study is done, filed, and signed
off.

## Gate C: native depth Capacitor plugins live in production

What the gate requires: native depth capture Capacitor plugins live in production
on BOTH iOS and Android, that is, TrueDepth and LiDAR on iOS and ARCore Depth on
Android, surfaced through the app shell.

Real current state (honest): UNMET. No native depth plugins exist anywhere in the
codebase. The tier resolver `src/lib/body-tracker/scan-tier.ts` declares the
capability inputs (`hasLidar`, `hasArCoreDepth`, `hasTrueDepth`,
`hasCompletedGenex360Panel`) but `resolveScanTier` returns Tier 1 unconditionally
and ignores every input. Tier therefore resolves to 1 only today; there is no live
path to Tier 2 (depth) or Tier 3 (genomic priors). The capture flow hardcodes
`tier: 1` and sends `depth_sensor_type: 'none'` to the analyze function. The
resolver's own header states Tier 2 and Tier 3 wire in once the device capability
APIs and genomics plumbing are in place, which they are not.

Gate C is UNMET: there are no native depth plugins, and tier is pinned to 1.

## Phase 2 entry decision

Phase 2 is entered only when all three gates close and Gary then issues the go:

1. Gate A closes: the parametric body model decision is taken (SMPL-X commercial
   license secured, or the MediaPipe GHUM mesh fallback committed and implemented).
2. Gate B closes: the Tier B clinical cohort is run (100 to 200 participants, same
   day DEXA plus scan, segmental DEXA), the model is trained and validated, the
   report is filed, and Gary signs off, with the 40,000 to 80,000 USD authorized.
3. Gate C closes: native depth Capacitor plugins are live in production on iOS and
   Android.

All three are necessary. With all three closed, Gary issues the explicit go to
start Phase 2. No Phase 2 work begins on gates alone; the go is a separate, human,
Gary owned decision.

## Deferred Prompt #169d items that return in Phase 2

The following capabilities were pulled out of Phase 1 and return in Phase 2 once
the gates above close. None of them exist in the codebase today:

- The 102 measurement extraction service plus its catalog seed (the full
  measurement catalog and the service that extracts all of it).
- The weight prediction CNN head.
- The segmental composition CNN head (per region body composition, the model the
  segmental DEXA data in Gate B trains and validates).
- Continuous rotation depth capture (the Tier 2 and Tier 3 capture experience,
  gated on Gate C native depth; Phase 1 ships only the discrete four pose flow,
  see `docs/formavision/specs/four-view-capture-flow-v1.md`).
- The interactive 100 plus landmark avatar (the dense landmark avatar that a Gate A
  parametric body model would make possible; today the avatar is the primitive
  mannequin with no dense landmark set, skeleton, or blend shapes).
- The heat map, symmetry, segment, and compare shader overlays on the avatar
  (advanced per region visualization; Phase 1 ships per segment coloring with a
  single whole body value, not true per region shader overlays, see
  `docs/formavision/avatar-inspection-v1.md`).
- The accuracy marketing claims, which are gated on the Tier B report (Gate B).
  No accuracy or DEXA equivalence claim may ship until that study is filed and
  signed off.

## Phase 1 reality versus Phase 2 target

So no one assumes the deferred capabilities already exist:

| Capability | Phase 1 reality (shipped) | Phase 2 target (gated) |
| --- | --- | --- |
| Avatar mesh | Custom primitive parametric (spheres plus cylinders), 9 parameters | Landmark dense parametric body model (SMPL-X licensed or GHUM), interactive 100 plus landmarks |
| Tier | Tier 1 only; `resolveScanTier` ignores inputs | Tier 2 (depth) and Tier 3 (genomic priors) live |
| Depth capture | None; `depth_sensor_type: 'none'`, discrete four photo flow | Continuous rotation depth capture via native plugins |
| Composition | Whole body anthropometric estimate (Navy plus CUN-BAE plus vision range) | Weight prediction and segmental composition CNN heads, 102 measurement extraction |
| Avatar overlays | Per segment coloring driven by one whole body value | Heat map, symmetry, segment, and compare shader overlays |
| Accuracy claims | None permitted; literature figures are design targets only | Permitted only after the Tier B validation report is filed and Gary signs off |

Phase 1 is an honest Tier 1 build. Treat every Phase 2 capability as not yet
present until its gate closes and Gary issues the go.

# Prompt 210d Wave P1: Subsystem Activation Decision Sheet

Date: 2026-07-07. Branch: feat/210d-schema-integrity. Read-only analysis; no migration applied here.
Sources: docs/integrity/snapshot/phantom-remediation-map.json, phantom-severity.json, edge-function-parity.json, docs/integrity/schema-drift-report.md, repo migration files, src nav configs.
Scope: 14 clusters of phantom objects whose creating migrations sit unapplied in the repo (or do not exist). One decision per cluster: APPLY TRANCHE (apply the unapplied repo migrations), RETIRE CODE (remove or repoint the referencing code), or LEAVE TAGGED (keep the fail-open tag, no action this wave).
Reachability terms: nav-reachable (linked from a sidebar or hub tile), direct-URL-only (page exists, zero inbound links found in src), dormant-module (referencing file has no importers).
Cross-cluster caveat: nearly every cron or pipeline edge function referenced below is in the repo but NOT deployed live (edge-function-parity.json in_repo_not_deployed: vest-referral-rewards, expire-referral-credits, practitioner-waitlist-mailer, cert-reminder-tick, archetype-refinement-tick, unit-economics-snapshot-tick, brand_compliance_validator, arnold-tick, payout_statement_generator, tax_form_year_end_generator). Applying a tranche activates web surfaces immediately; the automated pipelines additionally need function deploys, which are a separate P2+ step.
